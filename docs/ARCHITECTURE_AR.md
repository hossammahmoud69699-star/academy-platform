# معمارية المنصة

## المكونات

1. **Student Android App**
   - تسجيل الدخول وعرض الكورسات.
   - عرض المحاضرات والتقدم والاختبارات والأكواد.
   - لا يتصل بقاعدة البيانات بصلاحيات إدارية.
2. **Admin Web**
   - إدارة الطلاب والمدرسين والمحتوى والامتحانات والأكواد.
   - جميع العمليات الإدارية تخضع للتحقق من الدور في قاعدة البيانات/الخادم.
3. **Supabase**
   - PostgreSQL لتخزين البيانات.
   - Auth لإدارة الهوية والجلسات.
   - Storage للملفات الخاصة.
   - Row Level Security (RLS) لعزل بيانات كل دور.
   - Edge Functions للعمليات التي تتطلب أسرارًا أو تحققًا على الخادم.
4. **GitHub Actions**
   - بناء Android لاحقًا من مستودع المشروع.
   - لا تُحفظ الأسرار داخل ملفات المصدر.

## تدفق طلب تشغيل محاضرة مدفوعة

1. يسجل الطالب الدخول.
2. يطلب التطبيق بيانات الكورس.
3. تتحقق سياسة RLS من المستخدم وصلاحياته.
4. يتحقق الخادم/الوظيفة من وجود اشتراك نشط أو تفعيل صحيح.
5. يحصل التطبيق على رابط مؤقت للمحتوى إذا كانت خدمة التخزين تدعم ذلك.
6. تسجل أحداث المشاهدة بشكل دوري مع التحقق من الصلاحيات.

## الأدوار الأولية

- `super_admin`: إدارة النظام بالكامل.
- `teacher`: إدارة الكورسات المصرح بها ومتابعة طلابها.
- `student`: الوصول إلى المحتوى المفعّل لحسابه.

## قرارات مؤجلة للاعتماد قبل الإنتاج

- مزود بث الفيديو وDRM؛ حماية DRM الكاملة غالبًا ليست مجانية.
- مزود OTP ورسائل SMS في مصر.
- بوابة الدفع الإلكتروني المحلية.
- مدة الاحتفاظ بأحداث المشاهدة والبيانات الشخصية.
- إعدادات النسخ الاحتياطي وخطة الاستعادة.

## حدود النسخة الأولية

الخطة المجانية مناسبة للتطوير والاختبار المبدئي، وليست وعدًا باستضافة مجانية غير محدودة. لا يمكن ضمان منع تسجيل الشاشة أو التصوير الخارجي بالكامل.
